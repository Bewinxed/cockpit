## Fix Session Resumed Timing to Wait for instance:started

**Problem**: "Session resumed" system message appears immediately after the resume API call (line 918-922, 979-984), but Claude isn't actually ready until the `instance:started` SSE event arrives. This creates a gap where the user sees "Session resumed" but can't interact yet.

**Locations**:
- `WorkspaceInstance.svelte:918-922` - Adds "Session resumed" message after handleResume success
- `WorkspaceInstance.svelte:979-984` - Adds "Session resumed" after auto-resume in handleSend
- `instances.svelte.ts:810-960` - SSE event handlers

**Current flow**:
1. User sends message or clicks resume
2. API call to `/resume` endpoint
3. API returns success → "Session resumed" message added, `restarting=false`
4. ... gap ...
5. `instance:started` SSE event arrives → Claude is actually ready

**New flow**:
1. User sends message or clicks resume
2. API call to `/resume` endpoint
3. API returns success → `isResuming` remains true, no "Session resumed" yet
4. `instance:started` SSE event arrives → Add "Session resumed" message, `isResuming=false`

**Implementation**:

1. **Track resuming state per instance** in `instances.svelte.ts`:
```typescript
// In InstanceStore class
resumingInstances = $state<Set<string>>(new Set());

setResuming(instanceId: string, isResuming: boolean) {
  if (isResuming) {
    this.resumingInstances.add(instanceId);
  } else {
    this.resumingInstances.delete(instanceId);
  }
}

isResuming(instanceId: string): boolean {
  return this.resumingInstances.has(instanceId);
}
```

2. **Update `handleStarted`** in instances.svelte.ts to clear resuming and potentially add message:
```typescript
handleStarted(data) {
  // existing logic...
  if (this.resumingInstances.has(data.id)) {
    this.resumingInstances.delete(data.id);
    // Optionally emit event for "Session resumed" message
  }
}
```

3. **Update WorkspaceInstance.svelte**:
- Remove immediate "Session resumed" message after API call
- Set `instances.setResuming(instanceId, true)` before API call
- Keep `restarting` local state for UI indicator
- Listen for resuming state changes to add "Session resumed" when ready

4. **Consider**: Maybe don't show "Session resumed" at all - just let the natural message flow indicate Claude is ready. The ActivityGrid state change is enough feedback.
## Acceptance
- [ ] "Session resumed" message only appears after `instance:started` SSE event (or removed entirely)
- [ ] `isResuming` state tracked per instance in store

- [ ] No "dead air" where nothing appears to be happening
- [ ] `restarting` flag in WorkspaceInstance stays true until instance is actually started
- [ ] TypeScript compiles without errors
