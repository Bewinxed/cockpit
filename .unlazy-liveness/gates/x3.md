# Gates: X3 — the replay half of §7 (found by X2, reported not fixed)

X2 armed the dedupe: a replayed line is refused, proven by mutation (4 frames for 2 lines
when the stamp is deleted). That is "at most once".

The other half — "replay exactly the gap the hub names" — was unreachable in production:

    server.ts:3017
      ws.send(registerAck(message, streams.ingestedFor(peekInstances(message.payload))))

`peekInstances(payload)` is the daemon's own `supervisor.instanceIds`, which is EMPTY
immediately after a restart. So the ack a returning agent reattaches on carried `{}`, and
custody followed from head instead of replaying the named gap.

**THE ROUTE OUT OF THE CIRCLE — the hub answers it, not the daemon.**

The circle only binds if the *daemon* has to be the one to name the sessions. It does not.
The hub already knows both halves at the same instant: `settleInstances` has just decided
which orphans are revivable, and the `restore` spawns it sends for them are exactly the rows
the daemon will hand back to `reattachFrom`. So the ack's ledger is computed over
`reattachable(reported, restored)` — the union of the daemon's own live list and the ids the
hub just restored (`packages/hub/src/server.ts`, `reattachable` + the register ack site).

Rejected: widening `SessiondProcInfo` with the spec's `cwd`. It works, but it makes sessiond
a source of session metadata, which design §3.2 explicitly denies it ("the spec is built
entirely agent-side and handed over opaque: sessiond does not read, validate or enrich a
single entry of it") — `packages/sessiond/src/server.ts:326-327`. Also rejected: a second
register after adoption (a new round trip, and a window where the hub's truth column
disagrees with itself). The chosen route changes no protocol type, no daemon code and no
sessiond code — and therefore cannot break the other side of the circle, which is G3.
