## ⚠ ORDERING HAZARD, raised by leaf C1 — read before touching anything

`deployUpdate` passes `restartAgent: true`. **Post-cutover that restart is free**, because
the children live in sessiond's cgroup and survive it — that is the whole point of the
build. **Pre-cutover it is not free**: on a machine where the agent still owns its children,
an auto-update restarts the agent and destroys every live session on it.

The poller is inert until the marker exists (`deploy.ts:201` returns `unmarked` before any
git command runs, and `~/.cockpit` does not exist yet), so nothing can fire early by
accident. But it makes the cutover order load-bearing rather than cosmetic:

  **sessiond must be running and owning the children BEFORE `.cockpit-deploy` exists.**

If the marker is written first and a push lands on main before sessiond has custody, the
first auto-update is the destructive one. Sequence sessiond → verify custody (G2) → only
then `deploy init`.

Also from C1: `deployUpdate` refuses any state but `behind`, and a diverged clone refuses
loudly rather than resetting — so a hand-edited clone will stop deploying and say so, which
is the intended failure.
